# Spine Pair Review — WalkQuest

## Overall verdict

Пара спин крепкая и читаемая нижестоящими потребителями: токены полные, компоненты имеют и визуальную, и поведенческую спецификацию, решения зафиксированы, а не «взвешены». Риски — в покрытии: потерялся флоу запланированной прогулки (UJ-3), нет карточки POI и состояний Рейтинга. Всё исправимо точечными дописками.

## 1. Flow coverage — adequate

Проверено против PRD UJ-1…UJ-4: UJ-1 → Flow 1 (с граничными случаями), UJ-2 → Flow 2, UJ-4 → Flow 4. Связь по ID не записана явно (см. §7).

### Findings
- **[high]** UJ-3 (запланированная прогулка с напоминанием) не имеет Key Flow (EXPERIENCE.md §Key Flows). *Fix:* добавить Flow 5: создание плановой прогулки → напоминание → старт; включая отмену/перенос.
- **[medium]** Нет поверхности управления запланированными прогулками (список, редактирование, удаление) — карточка на панели Карты показывает только ближайшую (EXPERIENCE.md §IA). *Fix:* добавить поверхность «Планировщик» в IA (под Профилем или раздел на Карте-панели).

## 2. Token completeness — strong

Все токены frontmatter определены, пары light/dark на месте, ссылки `{path.to.token}` разрешаются. Контрастная рамка заявлена (4.5:1, dim осветлён).

### Findings
- **[low]** `bottom-nav.background: '#141020'` — только тёмное значение; светлое (#FBF9FD в макете) не токенизировано (DESIGN.md frontmatter). *Fix:* добавить `surface-nav` пару light/dark.
- **[low]** `card-active.background: 'accent 8% alpha'` — alpha-запись не hex; допустимо как семантика, но отметить, что резолвер считает от accent (DESIGN.md frontmatter). *Fix:* пояснить формат alpha-токенов одной строкой.

## 3. Component coverage — adequate

Сверены имена компонентов обеих спин: toggle-mode, sheet, button-primary, card-task, quest-card, ach-item, bottom-nav — обе стороны покрыты.

### Findings
- **[high]** Карточка POI (тап по маяку → название + описание) отсутствует в обеих спинах, хотя FR-18 её требует (DESIGN.md §Components, EXPERIENCE.md §Component Patterns). *Fix:* добавить poi-card: визуал (card, поверх карты, нижняя зона) и поведение (тап по маяку открывает, свайп/тап вне закрывает, офлайн-контент из кеша).
- **[low]** `card` (generic) есть в DESIGN.md, но не упомянут в EXPERIENCE.md Component Patterns. *Fix:* одна строка поведения или явное «визуальный базовый элемент».

## 4. State coverage — adequate

Карта, Прогулка, Онбординг, Прогресс покрыты состояниями (офлайн, permission-denied, пустая история, потеря процесса, батарея).

### Findings
- **[medium]** Рейтинг без состояний: ник не задан (первый вход), нет друзей, офлайн, пользователь скрыл себя из рейтингов (EXPERIENCE.md §State Patterns). *Fix:* 3-4 строки состояний.
- **[low]** Регионы: состояние «регион загружается» (прогресс скачивания десятков МБ) не описано. *Fix:* строка в State Patterns.

## 5. Visual reference coverage — adequate

EXPERIENCE.md §IA ссылается на 5 макетов с пояснениями; правило «спина важнее макета» записано.

### Findings
- **[low]** `mockups/color-themes-1/2.html` — осиротевшие (исследовательские палитры, не спецификация). *Fix:* пометить как exploration-архив в UX-индексе или исключить из mockups/.
- **[low]** DESIGN.md не ссылается на макеты вообще. *Fix:* одна ссылка в §Components на соответствующие макеты.

## 6. Bloat & overspecification — strong

Пиксельных переспецификаций нет; PRD не пересказывается; таблицы вместо прозы. EXPERIENCE.md проза по делу.

## 7. Inheritance discipline — adequate

`sources` разрешается; терминология интерфейса (Достижения, Задания, Регион, Туман) консистентна с PRD-глоссарием.

### Findings
- **[medium]** Key Flows не привязаны к UJ-ID из PRD (Flow 1–4 без «реализует UJ-1»). *Fix:* добавить маппинг в заголовки флоу.

## 8. Shape fit — strong

DESIGN.md: все секции в каноническом порядке. EXPERIENCE.md: все обязательные секции на месте; Inspiration & Anti-patterns заработана (есть референсы и отвергнутые паттерны); Responsive & Platform уместна (одна платформа, зафиксирован класс устройств).

## Mechanical notes

- Frontmatter обеих спин полный; `status: draft` до закрытия — корректно.
- Компонентные имена идентичны между файлами (проверено по таблицам).
- Mermaid нет, синтаксических рисков нет.
