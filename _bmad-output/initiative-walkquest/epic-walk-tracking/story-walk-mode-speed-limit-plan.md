# План истории 2.2 — Режим прогулки и лимит скорости по режиму

Эпик: epic-walk-tracking · Тикет: 2.2 (tickets.toml) · Дата: 2026-10-09
Ссылки: FR-6, PRD OQ-1 (точные лимиты — spike 2.3), AD-5. После 2.1 (WalkSession).

## Решения

- `tracking/WalkMode.kt`: enum `WALKING` (по умолчанию) / `CYCLING` (вело/самокат) +
  `SpeedLimitPolicy` — единый резолвер эффективного лимита: пользовательский
  override из настроек ?: дефолт из `SpeedLimits` (12/30 км/ч — гипотезы OQ-1).
  Дефолты НЕ меняем здесь — калибровка в spike 2.3.
- `PointFilter.updateLimit(limitMps)`: смена лимита на лету (переключение режима
  ВО ВРЕМЯ прогулки): обновляет и порог телепортации (произведение лимита).
  Якорь не трогаем — смена режима не делает честную точку телепортацией.
- `SettingsRepository`: + `walkMode()`/`setWalkMode` (последний выбранный режим,
  переживает перезапуск) и + `walkSpeedLimitKmh(mode)`/`setWalkSpeedLimitKmh(mode, kmh)`
  (nullable-override; null = дефолт режима). Поля с дефолтами — formatVersion не
  поднимаем (обратная совместимость, unknown keys игнорируются).
- Сервис: `ACTION_SET_MODE` (extra `mode`) — резолвит лимит через policy+настройки,
  `filter.updateLimit`; режим на старте записи берётся из настроек. Пауза/финиш
  не трогаем.
- Шина: `TrackingSnapshot.walkMode` — UI показывает активный режим при записи.
- UI (MapScreen): переключатель «Пешком / Вело» над кнопкой старта; виден и до,
  и во время записи; во время записи тап шлёт ACTION_SET_MODE. Выбор (до старта)
  персистится через viewmodel → SettingsRepository. Экрана настроек в продукте
  пока нет — редактирование числовых лимитов для 2.2: точка входа = debug-панель
  НЕ подходит (продуктовая настройка); честная точка входа — кнопка режима +
  хранилище override'ов, UI числового редактора отложен до экрана настроек
  (зафиксировано в deferred-work, не блокирует FR-6: лимиты режимов действуют).
- WalkSession.mode НЕ добавляем: прогулка может менять режим в середине, сессия
  хранит агрегаты, а не режимную историю (история режимов — Room-эпоха).

## Тесты (JVM)

- PointFilter: updateLimit меняет допустимую скорость и порог телепортации;
  смена лимита в середине трека не сбрасывает якорь; граница лимита (ровно лимит —
  принято, чуть выше — отсечено) для обоих режимов.
- SpeedLimitPolicy: дефолт без override; override из настроек; оба режима.
- SettingsRepository: round-trip режима и лимитов; override null → дефолт;
  старый файл без новых полей читается (дефолты).
