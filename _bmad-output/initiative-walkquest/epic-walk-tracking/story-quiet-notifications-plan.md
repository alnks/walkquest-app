# План истории 2.7 — Тихие уведомления прогулки

Эпик: epic-walk-tracking · Тикет: 2.7 (tickets.toml) · Дата: 2026-10-09
Ссылки: FR-9. После 2.1–2.6.

## Решения

- Тихий канал: канал «tracking» уже IMPORTANCE_LOW (FR-9, с 1.7), walk-reminders
  (2.5/2.6) — тоже LOW. Runtime-разрешение POST_NOTIFICATIONS (Android 13+) —
  уже в RECORDING_PERMISSIONS с 1.7. Добавляемое в 2.7 — частота и содержимое.
- `tracking/NotificationThrottler.kt`: чистый JVM-троттлер — прогресс-
  уведомление не чаще, чем раз в интервал; первый показ — сразу (старт).
  Интервал — параметр из настроек.
- SettingsRepository: progressNotificationIntervalMinutes (default 5,
  валидация 1..120). Числовой UI — к экрану настроек (общий defer).
- Сервис: updateNotification() на КАЖДОЙ точке (сейчас) → через троттлер;
  текст прогресса: «Открыто клеток: N · X,X км · M мин» (агрегаты сессии,
  AD-4 — сервис только форматирует готовое). Процент открытия в прогресс-
  уведомление не добавляем: он — домен (AD-4), читать биткарту на каждый
  тик дорого; процент будет на финальном экране (2.8) и в UI карты.

## Тесты (JVM)

- NotificationThrottler: первый сигнал сразу, повторы в пределах интервала
  подавлены, после интервала пропущен, кастомный интервал, reset.
- SettingsRepository: round-trip интервала, валидация (0, 121 — отказ),
  дефолт 5, легаси-файл.
