# План истории 2.6 — Батарейный страж: предупреждение и автозавершение

Эпик: epic-walk-tracking · Тикет: 2.6 (tickets.toml) · Дата: 2026-10-09
Ссылки: FR-10, FR-8 (автозавершение открывает финальный экран — тот в 2.8).

## Решения

- `tracking/BatteryGuard.kt` — чистый JVM-детектор порогов заряда: вход — уровень
  заряда (%) по событиям; сигналы WarningDue (порог предупреждения, однократно,
  только при движении вниз через порог) и FinishDue (порог автозавершения,
  однократно). Пороги приходят параметрами (из настроек); рост заряда
  (подключили зарядку) сигналы не даёт — предупреждение не вернётся, но
  автозавершение всё равно сработает, если разряд продолжится (проверка <=).
- Значения по умолчанию 15%/10% (PRD FR-10). Пороги персистятся в
  SettingsRepository (batteryWarningPercent / batteryFinishPercent, валидация:
  оба > 0, warning >= finish). Числовой UI редактора — к экрану настроек
  (тот же defer, что и лимиты скорости 2.2); механика FR-10 работает на дефолтах.
- Сервис: BatteryManager.BATTERY_PROPERTY_CAPACITY читается на каждой принятой
  точке (дёшево, без ресивера) и на старте; FinishDue → stopRecording() (сессия
  завершается штатно: агрегаты сохранены, финальный экран — 2.8);
  WarningDue → тихое уведомление на канале walk-reminders (FR-9) с текстом PRD.
- Пауза/финиш сессии не конфликтуют: гвард работает на принятых точках, пауза
  только меняет учёт времени.

## Тесты (JVM)

- BatteryGuard: срабатывание на порогах (ровно на пороге — сигнал), однократность,
  рост заряда не повторяет предупреждение, порядок warning → finish,
  кастомные пороги, поведение после FinishDue (повторных сигналов нет).
- SettingsRepository: round-trip порогов, валидация (warning < finish отклонено,
  неположительные отклонены), дефолты 15/10, легаси-файл.
