### Результаты по шагам

1. **Первый вход** — экран «Придумайте ник», поле, «Вступить в рейтинг», «Остаться невидимым». ✅
2. **Вступить с ником** `LiveRunner8` → ❌ **«Не удалось сохранить ник — проверьте сеть»**.
   Воспроизведение curl'ом:
   ```
   POST /rest/v1/profiles {"nickname":"LiveRunner8"}
   → 401 {"code":"42501","message":"new row violates row-level security policy for table \"profiles\""}
   ```
   Причина: RLS-политики написаны под `auth.uid()` (предполагался Supabase Auth), а клиент
   (LeaderboardApi) ходит с чистым anon-ключом без авторизации — Auth в приложении нет.
   Дополнительно проверено: `POST /aggregates` и `POST /invites` → те же 401. То есть
   записывающий путь целиком заблокирован на живом сервере.
   (Заодно подтверждена клиентская валидация: Enter в поле даёт «уберите пробелы по краям».)
3. **«Остаться невидимым»** → ✅ топ реальных (seed) пользователей отрисован:
   «Тестер_Марафон 421,9 км · 87,0 %» … «Тестер_Гулял 31,6 км · 18,0 %», строка
   «Вы: невидимый режим». Live-данные реального PostgREST, сортировка по distance_meters.desc.
4. **Сегмент «Друзья»** → ✅ пустое состояние «Пока здесь только вы. Пригласите друга по ссылке»
   (создание инвайта тоже дало бы 401 — кнопка есть, сервер отклонит).
5. **«Обновить»** → ✅ без notice «Рейтинг недоступен» — успешный перезапрос топа (7.13-фикс
   снятия notice работает против живого сервера).

## 6. HITL — что нужно от владельца

Записывающий путь рейтинга невозможен против боевого проекта без серверного решения —
клиентский код менять вне этой стори не стал. Варианты (на выбор владельца):

1. **Anonymous Auth** (рекомендуется, минимальные изменения клиента): включить anonymous
   sign-ins в проекте, при первом вступлении `supabase.auth.signInAnonymously()` → далее
   `auth.uid()` работает, RLS-политики остаются как есть. Затем повторить прогон: своя строка
   с чипом «вы», публикация агрегатов, инвайты/друзья.
2. **Ослабить RLS под v1-контракт** (никто не авторизуется): default `gen_random_uuid()` для
   `profiles.id`/`aggregates.user_id` + anon-insert-политики. Минус: строки агрегатов не будут
   привязаны к профилю (случайный user_id) → своя строка в топе не появится без переноса
   identity на клиент (например, хранить uuid в настройках и слать в теле).
3. Оставить рейтинг read-only до отдельной стори.

**Вердикт: чтение рейтинга проверено живьём (боевой клиент ↔ живой Supabase) ✅;
запись — заблокирована RLS боевого проекта, требуется решение владельца (варианты выше).**
