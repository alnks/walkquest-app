### `app/src/main/java/app/walkquest/ui/settings/SettingsScreen.kt` — перестройка в 4 группы

Экран пересобран по AL-8 (макет `remaining-screens.html` v3, секция «Настройки»,
+ compare/README строка 11-settings и «Осталось» №5):

1. **«Цель»** — `WqCard` + `WqValueRow` («Моя цель», без действия) + `WqValuePill`
   со значением `walkGoal.describe()` (акцентная пилюля, как `.pill.on` в макете).
2. **«Прогулки»** — существующие действующие настройки без изменений поведения:
   выбор режима «Пешком / Вело» (`onWalkModeSelected`) и три `SwitchRow`:
   автопауза (`onAutoPauseToggled`), напоминание о забытой прогулке
   (`onForgottenReminderToggled`), кнопка «Задания» (`onShowQuestButtonChanged`).
   Свитчи на токенах акцента (`checkedTrackColor = accent`, ползунок `white`) — как было.
3. **«Уведомления»** — `WqValueRow` + пилюля «по умолчанию системные» **без действия**:

   режим/автопауза/напоминание/кнопка задания/цель/онбординг/ник/участие).
4. **«Внешний вид»** — `WqValueRow` «Тема» + пилюля «системная» **без действия**
   (решение по теме — ниже).

Сохранены: заголовок `headingScreen`, явный выход «Готово» (`WqPrimaryButton`
во всю ширину, spec §10), подпись-успокоение из спеки §10, каркас
(surface-base + statusBarsPadding + скролл, поля lg, зазоры md).

Подписи групп — sentence case по макету v3 («Цель», «Прогулки», «Уведомления»,
«Внешний вид»; раньше было «ПРОГУЛКА»). Строки/пилюли — существующие

### `app/src/main/java/app/walkquest/viewmodel/MapViewModel.kt` — цель в состоянии

- В `MapUiState` добавлено поле `walkGoal: WalkGoal? = null`, в `init` читается
  из `settingsRepository.walkGoal()` (источник тот же, что у Profile/Stats).
- **Дефект, найденный on-device прогоном:** `walkGoal` читался только в init,
  а цель выбирается в онбординге *после* init ViewModel → группа «Цель» показывала
  «—» до перезапуска приложения. Исправлено: `onOnboardingComplete(goal)`
  публикует цель в состояние (`it.copy(showOnboarding = false, walkGoal = goal)`).

## Решение по теме: БЕЗ ДЕЙСТВИЯ (пилюля «системная»)

Ручной выбор темы **не подтверждён** ни одним источником истины:

- EXPERIENCE.md: «Тёмная и светлая темы следуют системной настройке; тёмная —
  первоклассная» (и в таблице экранов нет выбора темы).
- DESIGN.md: «обе следуют системной настройке», раздел «Сознательные нет»,
  компоненты темы — только следование системе; переключателя темы нет.
- screens-spec.md §10: состав настроек — только «ПРОГУЛКА»-группа, темы нет.
- compare/README (11-settings): «тема — всегда системная».

По заданию 7.8 («если молчат — без действия») реализована неактивная пилюля.
Если появится ручной выбор — отдельной сторёй (нужны: спека поведения,
персист выбора, пересоздание активности).

## Отступления от макета (зафиксированные, осознанные)

1. **«Цель» — одна строка «Моя цель» вместо двух** («Отсчёт цели»/«Значение цели»):
   задание 7.8 формулирует группу как «значение — текущая цель»; единая
   строка `describe()` («3 прогулки в неделю») несёт оба факта.
2. **«Прогулки» — без «Автозавершение при разряде»**: такой настройки в коде нет,
   за пределами AL-8; добавление мёртвой пилюли запрещено заданием 3.
3. **«Уведомления» — одна строка** вместо трёх («Напоминания по цели» /
   «Запланированные прогулки» / «Во время прогулки»): каналов-настроек в коде нет,
   пилюли «вкл»/«тихие» были бы фикцией. Значение «по умолчанию системные»
   дано самим заданием 7.8.
4. **Свитчи с подписями** (title + subtitle) вместо пилюль «вкл» у переключателей:
   так требует screens-spec.md §10 (SwitchRow с title/subtitle); спина важнее
   макета (EXPERIENCE: «При конфликте спина важнее макета»). Макет v3 рисует
   эти же настройки пилюлями — расхождение макета и спеки, не реализации.
5. Подпись-успокоение и кнопка «Готово» — из спеки §10, в макете обрезаны рамкой.
