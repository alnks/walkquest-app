# Сведение дизайна экранов к утверждённым макетам

## Description

Кодовая дизайн-система (токены WqTheme, компоненты ui/components, шрифты Nunito/Manrope/Rubik Bubbles) внедрена, но ряд экранов визуально расходится с утверждёнными макетами — сверка 2026-10-12 (compare/README.md, отчёт compare/index.html). Эпик закрывает расхождения: каждый экран приводится к макету одной стори, в конце каждой — повторный скриншот в ту же сверку. Тексты и навигация (4 вкладки) не меняются; дизайн-решения принимаются по DESIGN.md/EXPERIENCE.md (спина важнее макета), макеты — где спина молчит.

## Outcome

Повторная сверка «макет ↔ реализация» показывает совпадение по всем экранам: владелец листает compare/index.html и не находит расхождений из списка «Осталось» — каждое либо закрыто, либо зафиксировано как переутверждённое решение.

## Requirements

Источник — ux-walkquest/compare/README.md (таблица сверки и «Осталось») и mockups/*.html. Родительские id не выделяются: работа сквозная по UI-слою, идентификаторы AL-<n> привязаны к экранам спецификации (screens-spec.md §).

- AL-1 Онбординг — 4 шага EXPERIENCE (приветствие с иллюстрацией-туманом и точками → домашний регион → цель со степпером → доступ к геолокации), как в mockups/onboarding-duo.html; обучение не пропускаемо, «Пропустить» ведёт к цели.
- AL-2 Финал прогулки — hero-процент, сетка из 3 карточек (км/время/серия), карточка нового достижения, «Поделиться результатом»/«На карту», без прокрутки, навигация под оверлеем скрыта (mockups/map-duo.html «Финал»).
- AL-3 Профиль — компоновка по макету remaining-screens «Профиль»: шапка (ник/аватар, статус участия), группы строк с пилюлями-значениями (Ник в рейтинге, Участие в рейтинге, Моя цель, Мои регионы, Перенос прогресса, Обратная связь), секция «О приложении».
- AL-4 Прогресс · Статистика — hero «17,4%» + сетка 6 карточек + список средних метрик (mockups/progress-tasks-duo.html «Статистика»).
- AL-5 Достижения — секции «Полученные / Неполученные» со сворачиванием; неполученные с пунктирной рамкой, у близких — полоска прогресса.
- AL-6 Задания — активное задание строго card-active; история «Выполненные» по макету; формулировки кнопок EXPERIENCE («Вытянуть карту» остаётся).
- AL-7 Рейтинг — сегменты «Город/Друзья» (WqSegmentPill), строки лидерборда с подсветкой текущего пользователя card-active, состояние первого входа по макету (CTA-карточка «Придумайте ник»).
- AL-8 Настройки — группы «Цель / Прогулки / Уведомления / Внешний вид» со значениями-пилюлями, включая «Тема: системная» (remaining-screens «Настройки»).
- AL-9 Регионы — мелкая сверка: строки по макету, навигация под оверлеем не дублирует выход «Готово».
- AL-10 POI-карточка — полоса фото (до 3) по макету, карточка прибита к нижней зоне над навигацией в idle-состоянии.
- AL-11 Карта (главная) — процент открытия только в панели (дубль плашки в шапке убрать или переутвердить); панель и CTA строго по макету.
- AL-12 Прогулка (запись/пауза) — третья метрика «+0,4% открыто» вместо «клеток открыто»; «+ Задание» пилюлей; «Завершить» — призрак с подтверждением УДЕРЖАНИЕМ ~600 мс (EXPERIENCE), не диалогом.

## Done when

1. По каждому из 12 экранов повторная сверка (compare-stitch) показывает совпадение с макетом в обеих темах; оставшиеся расхождения записаны в compare/README.md как переутверждённые решения.
2. Все экраны на токенах WqTheme и компонентах ui/components; новых hex вне файлов токенов нет (grep-проверка), минимальный кегль ≥12sp.
3. gradlew testDebugUnitTest зелёные (JDK 17), compileDebugKotlin без ошибок, @Preview компонентов собираются.
4. Дифы viewmodel/data/tracking — только строго необходимые для UI (например, флаг текущего пользователя в строках рейтинга), без изменения поведения.
5. Дизайн-работа каждой стори велась через плагин ui-ux-pro-max (навыки ui-ux-pro-max:ui-ux-pro-max и design-system) под Jetpack Compose — выбор токенов/спецификаций компонентов не «на глаз».

## Boundaries

Только UI-слой: ui/theme, ui/components, экраны ui/*, MainActivity. Не входит: новые функции и изменение текстов (копии утверждены EXPERIENCE; любые правки слов — отдельным согласованием), бизнес-логика viewmodel/data/tracking (кроме минимального дифа ради UI), сезонные палитры v2, переводы.
