# Story 7.7 — Рейтинг по макету (pixel-perfect сверка)

Дата: 2026-10-14. Статус: сделано, on-device сверка пройдена.

## Что сделано

Экран «Рейтинг» приведён к утверждённому макету из
`mockups/remaining-screens.html` (секция «Рейтинг») в рамках AL-7. Дизайн-
интеллект (ui-ux-pro-max:ui-ux-pro-max + ui-ux-pro-max:design-system): tap-area
строк ≥48dp, подпись строки сжимается (weight), значение — одна строка;
трёхслойная токенная архитектура — ни одного hex вне `ui/theme`.

### 1. Сегменты «Город / Друзья» — WqSegmentPill

Текст-кнопки `[ Город ]` заменены на `WqSegmentPill` (контурный активный
сегмент из 7.4: accentSoft-заливка + accentSoftBorder-рамка + accentText —
компонент не менялся). Показываются всегда (и на первом входе — по макету),
рядом текст-кнопка «Обновить» (спека §7).

### 2. Строки лидерборда — новый компонент WqLeaderboardRow

`app/src/main/java/app/walkquest/ui/components/WqLeaderboardRow.kt`: место
(Nunito 1000 — новый токен `typography.rank`, 18sp), ник, значение метрики
справа; фиксированная колонка ранга 32dp (макет `.lb-rank`), ник в одну строку
с многоточием. Цвета сэмплированы с рендера макета (обе темы): ранг и значение
лидера (место 1) и своей строки — `accentText`, остальные — `inkPrimary`;
ник в своей строке — `inkHeadline`. Медалей/аватаров в макете нет. Подсветка
текущего пользователя — `WqCardActive` + чип «вы» **сразу после ника** (макет
.me-row «olya_walks [вы]»; значение метрики прижато к правому краю — ник с
чипом живут в весовой колонке, сжатие длинного ника многоточием через
`weight(fill = false)`; позиция чипа исправлена по ревью родителя:
был прижат вправо к значению). Чип (.me-chip: тёмная — заливка accent + текст
accentInk; светлая — белая заливка, рамка 1.5dp и текст accentText). Флаг
`isCurrentUser` — минимальный диф в `RatingViewModel` (`RatingEntryUi`,
маппинг в `refresh()`); сетевой слой не трогался.

### 3. Первый вход — CTA-карточка «Придумайте ник»

Форма обёрнута в `WqCard` по макету `.nick-cta`: заголовок «Придумайте ник»,
подпись макета «Так вас увидят другие. История передвижений остаётся на
устройстве — в рейтинг уходят только ник и цифры.», поле ника, ошибка валидации
(`error`), `WqPrimaryButton` «Вступить в рейтинг», текст-кнопка «Остаться
невидимым» (ink-secondary). Утверждённые EXPERIENCE копии/поведение сохранены.
Новое: выбор «Остаться невидимым» переводит экран в честное основное состояние
(флаг `declined` в `RatingUiState`; персистентность косвенная — ник не задан +
участие выкл) — «Вы: невидимый режим» + пустой список, форма не донимает
(EXPERIENCE: «можно закрыть и не участвовать»).

### 4. Состояния (спека §7)

- loading: `CircularProgressIndicator` вместо списка (простой индикатор, §7);
  топ подгружается при первом показе вкладки (`LaunchedEffect`).
- пусто: «Пока пусто — станьте первым.» (город).
- «Друзья»: пустое состояние по спеке «Пока здесь только вы. Пригласите друга
  по ссылке» + код приглашения/«Пригласить друга»/поле кода/«Принять
  приглашение» (вкладка «Город» больше не смешивает приглашения со списком);
  бэкенда дружбы нет (v1 — invite-коды) — честное пустое состояние.
- ошибка сети: notice «Рейтинг недоступен (сеть/проект)» + кнопка «Понятно».
- скрытый из рейтингов: строка «вы скрыты; включите участие в настройках»
  (EXPERIENCE).

### 5-6. Иконки и формат чисел

Иконок/медалей в макете нет (эмодзи макета — плейсхолдеры по DESIGN Shapes).
Формат метрики — «км · %» с десятичной запятой, явная ru-локаль
(`String.format(Locale("ru"), …)`), спека §7.

## Расхождения макет ↔ спека и их разрешение

1. **Метрика строки**: макет показывает только «41%», спека §7 — «км · %»
   → спина важнее (правило EXPERIENCE), в реализации «41,2 км · 41,0%».
2. **Строка «Вы: ник» и «Обновить»**: в макете отсутствуют, спека §7 требует
   → сохранены.
3. **Кегль чипа «вы»**: макет 9px → увеличен до meta 12sp (минимальный кегль
   приложения, DESIGN Typography).
4. **Строки лидерборда при первом входе**: в макете под CTA-карточкой показаны
   демо-строки; реализация показывает только CTA (топ недоступен без ника,
   VM-гарда сетевого слоя) — честное состояние.
5. **Акцент ранга/значения у лидера (место 1)**: есть в макете (обе темы),
   в спеке не описан — реализовано по макету, зафиксировано здесь.

## Открытые вопросы

1. **Живая проверка списка — HITL** (см. «Серверный статус»): после
   восстановления проекта Supabase открыть вкладку на устройстве владельца:
   вступить с ником → своя строка подсвечена, топ реален.
2. **Офлайн-кеш топа с пометкой «данные на [время]»** (спека §7) в VM не
   реализован — сейчас ошибка сети = notice, без последнего кеша. Кандидат
   в отдельную микро-историю.
3. **Возврат к форме ника для «невидимого» пользователя** невозможен из самой
   вкладки (нет UI-пути; тоггл «Участие в рейтинге» в Профиле возвращает форму
   только после пересоздания VM). Микро-история при желании.
4. Синхронизация `RatingViewModel` с изменениями настроек из Профиля —
   в памяти VM состояние читается один раз (до пересоздания процесса) —
   прежнее поведение, не менялось.
5. Mock-сервер `_qa/mock-leaderboard-server.py` оставлен в `_qa/` как tooling
   для повторной сверки; запуск: `python _qa/mock-leaderboard-server.py` +
   `supabase.url=http://10.0.2.2:8791` в local.properties.
6. Мелочь из пересъёмки: ветка `Result.Ok` не очищает `notice` — после одной
   сетевой ошибки пометка «Рейтинг недоступен» висит и после успешных
   обновлений, пока не нажмёшь «Понятно». Кандидат в микро-правку
   (`it.copy(..., notice = null)` в Ok-ветке).
