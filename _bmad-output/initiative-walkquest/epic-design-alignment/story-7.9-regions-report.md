### Строки региона — сверены, изменений не потребовали

Существующая реализация `RegionsScreen.kt`/`RegionRow` уже совпадает с макетом и
спекой §9 по всем пунктам AL-9:

- Процент `headingCard`: домашний — `accentText`, чужие — `inkSecondary` (макет
  «17%» акцентом у домашнего).
- Название `headingCard` (Nunito 800, ink-headline), подпись `meta` (ink-dim):
  «домашний регион» / «установлен» — ровно копии из спеки §9.
- Формат чисел — ru-локаль, запятая («0,0%»), единое место форматирования
  (`formatPercent`), порог «<0,1%» для долей процента.
- Действия строк сохранены и работают: тап по строке → карта региона на вкладке
  «Карта»; «Обновить» (при версии выше в манифесте, «Обновляется…» блокирует
  прочие обновления); «Домашний» — персистентная смена домашнего региона.
- Иконок в макете нет — не добавляли.
- Выход — `WqGhostButton` «Готово» внизу списка (spec §9: «внизу списка … явный
  выход; стрелок нет»), компонент на токенах `button-ghost` (transparent, рамка
  `borderStrong` 1.5dp, текст `inkSecondary`, radius full) — проверено.

## Отступления и открытые вопросы

1. **Счётчики прогулок в meta.** Макет показывает «домашний регион · 21 прогулка» /
   «2 прогулки»; в приложении — «домашний регион» / «установлен». Спека §9
   определяет meta именно так, EXPERIENCE.md: «спина важнее макета»; счётчика
   прогулок в спеке нет, данных «прогулки по региону» в domain нет. Принято по
   спеке; если родитель решит иначе — нужен отдельный кросс-эпик тикет
   (domain + viewmodel + строка).
2. **Процент с десятой.** Макет — целые («17%»), приложение — «0,0%» / «17,4%»
   (как рейтинг и финал прогулки; ru-локаль соблюдена). Если для строк регионов
   нужен целый процент — однострочная правка `formatPercent`, но тогда строка
   разойдётся с финалом/рейтингом.
3. **Макет-сырьё `compare/_mock/10-regions-*.png` содержит нижнюю навигацию**
   (HTML-макет рисует «Регионы» как экран с bottomnav). После скрытия навигации
   в реализации склейка разойдётся по нижней зоне — это ожидаемое и правильное
   расхождение (compare/README фиксирует: «в макете нижней навигации под
   оверлеем нет»). Если нужна пиксель-в-пиксель сверка — сырьё надо перерендерить
   без bottomnav (вне моих полномочий).
4. **Один регион на устройстве.** Seed spb-city/v6 без прогресса → одна строка
   «0,0%», домашний по HomeRegionPolicy (settings.json без homeRegionId).
   Макет рисует три региона — состояние данных, не дефект вёрстки.
5. **Оверлей «Настройки» (7.10)** — под ним навигация по-прежнему видна
   (тот же дефект, вне скоупа 7.9). Рекомендация: та же однострочная правка
   (`&& !settingsOverlayVisible`) в сторе 7.10.
6. Строка 10-regions в `compare/README.md` не обновлялась (статус «Частично») —
   обновление статуса оставляю родителю после проверки склеек.
