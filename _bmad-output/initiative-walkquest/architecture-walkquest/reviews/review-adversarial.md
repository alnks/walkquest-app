# Review: adversarial (два юнита уровня ниже) — architecture-walkquest

Дата: 2026-10-01. Метод: конструирую пары юнитов (эпиков/пакетов), которые формально следуют всем AD, но расходятся между собой.

## Найденные пары и статус

1. **Экран карты vs экран статистики: два подсчёта процента.** Закрыто AD-4: единый владелец в domain, UI берёт готовое. ✅
2. **Tracking vs карта: кто открывает тайлы.** До правки была дыра: карта могла бы открывать тайлы по сырым GPS-точкам в обход лимита скорости. Закрыто правкой AD-4: биты открываются только через domain после фильтрации tracking. ✅ (fix applied)
3. **Прогулка на границе регионов (СПб/Ленобласть, Гатчина): два юнита могут по-разному приписать прогулку региону** (по экрану карты vs по границам). Закрыто правкой AD-9: принадлежность определяется только в domain по границам пакета. ✅ (fix applied)
4. **Серии: «день» по UTC vs по локали устройства.** Два юнита (статистика и напоминания) могли разойтись. Закрыто конвенцией: дни для серий и целей — локальный календарь устройства. ✅ (fix applied)
5. **Экспорт/импорт vs миграции Room:** файл экспорта и схема БД могут разъехаться. Смягчено конвенцией `formatVersion` с первого релиза; детальный маппинг — уровень эпика «Перенос данных», в spine не тянем. ОК.
6. **Лидерборд vs приватность:** юнит лидерборда мог бы слать «ещё пару полезных полей». Закрыто AD-3 + AD-7 (исчерпывающий список полей, RLS). ✅
7. **Пакеты vs Supabase:** юнит скачивания мог бы положить пакеты в Supabase Storage «раз он уже есть». Закрыто AD-6 (явный запрет + лимит трафика). ✅
8. **Достижения из обновлений задним числом:** юнит ачивок мог бы проверять только «новые» прогулки. Закрыто конвенцией «проверка после каждой прогулки + задним числом по истории». ✅

## Вердикт

PASS после правок 2–4 (внесены в spine до записи отчёта). Остаточный риск 5 — сознательно оставлен на уровень эпика, зафиксирован здесь для будущего тикета.
